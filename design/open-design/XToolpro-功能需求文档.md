## 1. 产品概述

XToolpro 是一个本地优先的 Android 工具箱，将网络代理、设备清理、音视频提取和图片处理整合到一个统一应用中。四个指定开源项目是对应能力的**首选实现来源**，XToolpro 的工作重点是整合、适配、维护和统一体验，而不是重复开发它们已成熟提供的功能：

| 能力域 | 参考项目 | XToolpro 首版定位 |
| --- | --- | --- |
| 网络代理 | [FlClash](https://github.com/chen08209/FlClash) | VPN 连接、配置、节点与流量状态 |
| 清理工具 | [sdmaid-se](https://github.com/d4rken-org/sdmaid-se) | 垃圾扫描、分类预览、可恢复清理 |
| 音视频提取 | [ytdlnis](https://github.com/deniscerri/ytdlnis) | URL 解析、格式选择、下载队列与任务管理 |
| 图片工具 | [ImageToolbox](https://github.com/T8RIN/ImageToolbox) | 压缩、转换、裁剪、调整、批处理 |

**关键原则**：以统一产品壳和统一设计系统承载四个上游项目的成熟能力。每项能力按“官方可复用模块/依赖 > Fork 后模块化移植 > 受控独立进程集成 > 最小适配补充”的顺序决策；只有上游缺失、无法在目标 Android 版本运行、存在安全问题或许可证不允许时，才允许自研最小补充代码。不得未经许可证、依赖和安全审查复制上游品牌、UI 资源或后台服务。

## 2. 目标与成功指标

### 2.1 产品目标

1. 用户从首页在两次点击内进入任一工具。
2. 常用任务尽量在本地完成，减少数据上传和隐私风险。
3. 统一任务中心、通知、文件输出和设置，避免四套互不相干的体验。
4. 对代理、下载、清理等高风险操作提供可见状态、预览和撤销机制。

### 2.2 MVP 指标

- 首次启动到首页可用时间不超过 3 秒（中端 Android 设备）。
- 四个模块核心流程成功率不低于 95%。
- 崩溃率低于 0.5%，后台任务异常可恢复率不低于 90%。
- 清理操作 100% 支持结果预览；默认不删除用户明确标记的文件。
- 应用不收集文件内容、代理流量内容或下载媒体内容用于分析。

## 3. 用户与使用场景

### 3.1 目标用户

- 需要临时开启代理、切换节点的普通用户。
- 存储空间不足、需要定期维护设备的用户。
- 需要从公开 URL 获取音频/视频供离线使用的用户。
- 需要快速处理、压缩或批量转换图片的用户。

### 3.2 典型场景

1. 首页查看存储占用，扫描并清理缓存。
2. 导入代理配置，选择节点并开启 VPN。
3. 粘贴视频 URL，选择分辨率和音频格式，加入下载队列。
4. 从相册选择多张图片，批量压缩为 WebP 并保存到指定目录。

## 4. 产品范围

### 4.1 MVP 必须包含

- 首页、四大模块入口、统一任务中心和设置。
- 工具箱页自定义布局：分组、搜索、收藏、最近使用、拖拽排序、隐藏/恢复、卡片尺寸和恢复默认。
- 代理：配置导入/导出、节点选择、连接/断开、连接状态和基础流量统计。
- 清理：缓存/残留/大文件/重复文件扫描，结果分组预览，勾选删除，回收站或撤销窗口。
- 提取：URL 输入、媒体信息解析、格式/质量选择、下载队列、暂停/恢复/取消、失败重试。
- 图片：选择/拍摄导入、裁剪、旋转、缩放、压缩、格式转换、批处理、导出。
- 权限按需申请、隐私政策、开源许可与第三方声明页面。

### 4.2 MVP 不包含

- 账号体系、云同步、社交分享、在线网盘。
- 绕过付费、DRM、地区限制或平台访问控制。
- 自动静默清理、自动连接代理、后台无限制下载。
- 对系统分区、其他应用私有目录或 root 能力的承诺。

## 5. 信息架构与导航

底部导航固定为：**首页 / 工具 / 任务 / 设置**。

- **首页**：存储概览、代理快捷开关、最近任务、四模块快捷入口。
- **工具**：可自定义的工具箱首页，展示全部工具、收藏工具、最近使用和自定义分组。
- **任务**：下载、扫描、图片处理和导出任务，按运行中/已完成/失败分类。
- **设置**：输出目录、通知、主题、权限、隐私、许可、日志与诊断。

全局交互要求：统一顶部栏、按钮状态、错误提示、空状态、进度展示和无障碍标签；耗时任务必须使用 Android 后台任务机制并在通知栏显示状态。

### 5.1 工具箱页布局与自定义（P0）

工具箱页采用当前 Android 工具类常见的“分段筛选 + 分组区块 + 自适应网格”布局，重点是快速找到工具，同时允许用户按自己的工作习惯重新排版。

#### 5.1.1 默认视觉结构

1. 顶部应用栏：页面标题“工具箱”，右侧提供搜索和编辑入口；滚动时应用栏可收缩，但搜索入口始终可达。
2. 分段筛选栏：**全部 / 收藏 / 最近** 三个分段。切换不离开当前页面，筛选结果为空时显示对应空状态和恢复入口。
3. 推荐/最近区：默认展示最近使用的 4 个工具；用户没有历史记录时展示“开始使用”引导，不展示虚假数据。
4. 分组区块：默认分为“网络工具、设备维护、媒体工具、图片工具”四组；每组显示组名、工具数量和“查看全部”。
5. 工具卡片：使用图标、工具名称、简短状态/副标题；支持紧凑小卡片和宽卡片两种尺寸。卡片不得仅依赖颜色表达状态。
6. 底部悬浮操作区：编辑模式下显示“完成”和“恢复默认布局”；普通模式不遮挡最后一行工具。

#### 5.1.2 自定义能力

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| BOX-01 | 进入编辑模式 | 从工具箱右上角进入；编辑状态有明显标题和退出按钮，不误触启动工具 |
| BOX-02 | 拖拽排序 | 长按卡片拖动调整同组内顺序；拖动时有占位反馈，松手后位置稳定 |
| BOX-03 | 跨组移动 | 将工具拖到其他分组；移动前显示目标分组，移动后数量和顺序同步更新 |
| BOX-04 | 显示/隐藏 | 可隐藏不常用工具；隐藏工具仍可在“编辑 > 已隐藏”中恢复，不能隐藏搜索和编辑入口 |
| BOX-05 | 收藏 | 普通模式支持一键收藏/取消收藏；收藏工具出现在“收藏”分段并按用户顺序排列 |
| BOX-06 | 自定义分组 | 新建、重命名、删除分组；删除分组前必须选择“移动工具”或“同时隐藏”，不能无提示丢失工具 |
| BOX-07 | 卡片尺寸 | 每个工具可选紧凑卡片/宽卡片；布局切换不改变工具配置和历史记录 |
| BOX-08 | 分组折叠 | 支持展开/折叠分组；折叠状态独立保存，重启应用后保持 |
| BOX-09 | 恢复默认 | 支持恢复默认顺序、分组、可见性、卡片尺寸；恢复前二次确认，收藏状态可选择保留 |
| BOX-10 | 搜索 | 按名称、别名、功能关键词搜索；搜索结果可直接启动工具或进入编辑定位 |
| BOX-11 | 首次使用 | 首次进入展示一次性轻量提示，说明可编辑布局；用户关闭后不重复打扰 |
| BOX-12 | 分享入口 | 系统分享或快捷入口打开指定工具时，直接进入对应工具，不强制经过工具箱页 |

#### 5.1.3 响应式与交互规则

- 手机竖屏默认 2 列网格；宽屏手机/平板根据可用宽度自适应为 3-6 列，卡片最小宽度不小于 96dp。
- 横屏、分屏和大字体模式下不得出现卡片重叠、文字截断或拖拽目标不可见；工具名称最多两行，超出部分使用省略号并可通过无障碍朗读完整名称。
- 网格排序采用稳定布局算法，拖拽、插入和删除不会导致其他卡片瞬间跳动；动画时长建议 150-250ms，并遵循系统“减少动态效果”设置。
- 工具箱布局仅保存本地用户偏好；清除应用缓存不应清除布局，清除应用数据或卸载重装后恢复默认。
- 布局数据采用版本化 schema，未来新增工具时自动放入对应默认分组，不覆盖用户现有排序。
- 所有卡片、收藏按钮、拖拽手柄、折叠按钮和编辑入口提供 TalkBack 描述、触控目标不小于 48dp。

### 6.6 上游功能复用与等价清单（完整复制基线）

以下清单定义“复用上游软件能力”的范围。V0.1 锁定四个上游提交后，研发必须逐项标记复用方式、来源版本和差异状态。默认选择能保留最多上游成熟逻辑的方案，而非重新实现同类功能；等价指用户能完成同一任务，不要求复刻上游 UI、品牌或内部代码。

| 字段 | 强制记录内容 |
| --- | --- |
| 功能编号 | 与本文需求编号一一对应，例如 `PRO-01`、`IMG-04` |
| 上游来源 | 仓库、分支、tag 或不可变 commit SHA、对应代码路径/组件 |
| 复用方式 | 官方库/模块、Fork 移植、引擎适配器、受控独立进程、最小补充实现 |
| 差异状态 | 原样可用、UI 适配、Android 降级、上游缺失、许可证/安全阻断 |
| 验证证据 | 上游行为对照测试、真实设备结果、许可证和依赖审查记录 |
| 维护责任 | 上游更新策略、补丁负责人、回滚版本和已知限制 |

禁止把“功能相似的自研版本”标记为上游复用；如确实需要最小补充实现，必须记录上游缺口、替代方案和批准的 ADR。

#### 6.6.1 FlClash / Clash 客户端

- 本地 YAML、剪贴板、URL/订阅导入；订阅更新、失败回退、重命名、复制、删除、导出。
- 规则/全局/直连模式；代理组展开、节点切换、当前节点持久化。
- 节点协议/地区/标签筛选；单节点测速、批量测速、不可用节点标记。
- Android VPN 启停、连接状态、其他 VPN 占用提示；始终开启/断线阻止（系统支持时）。
- TUN、系统代理、局域网共享、IPv6、DNS、Fake-IP/Host、流量嗅探（内核和系统支持时）。
- 按应用代理/绕过、局域网绕过、域名/IP/GeoIP 规则集和命中日志。
- 实时上下行速率、会话流量、连接列表、请求/规则/内核日志和崩溃诊断。
- 内核版本显示/更新、配置校验、备份恢复、启动连接、自动更新、桌面快捷方式/小组件（设备支持时）。

#### 6.6.2 sdmaid-se / 设备维护

- 应用缓存、系统缓存、缩略图、日志、临时文件、空目录、安装包、残留目录和大文件扫描。
- 卸载残留识别、规则解释、逐项排除和误报反馈。
- 按应用查看占用；批量打开卸载/停用入口；无 root 时不模拟系统级删除。
- 重复文件按名称/大小/哈希分组，图片/视频/文档分类，保留项建议。
- 存储目录树、文件类型分布、最大/最近文件、路径搜索、排序和定位。
- SAF 范围内浏览、重命名、移动、复制、分享、删除、回收站恢复、安全擦除（设备支持时）。
- 已安装/系统应用列表、应用信息导出、冻结/停用等高风险操作的二次确认。
- 定时扫描、仅 Wi-Fi/充电执行、低电量跳过、通知摘要、执行历史。
- 全局搜索、白名单/黑名单、最近文件/收藏保护、排除路径、清理策略导入导出。

#### 6.6.3 ytdlnis / yt-dlp 前端

- 粘贴 URL、系统分享、批量 URL、播放列表/频道 URL、剪贴板识别开关。

- yt-dlp/FFmpeg 版本、组件更新、下载日志、解析错误、网络诊断和日志导出。
- 后台通知、完成动作、失败提醒、开机恢复未完成任务（用户显式开启时）。

### 6.7 功能开关与降级规则

- 每个高级能力有独立 feature flag 和设备能力检测，不因单项不可用阻塞模块主流程。
- 不支持 root、TUN、HEIF、硬件编码、OCR 或系统级删除时，显示原因和替代方案，不显示成功假象。
- 依赖缺失或版本不兼容时，任务中心显示错误码和修复入口；禁止静默下载未知二进制。
- 所有差异进入兼容性矩阵，按 Android 版本、ABI、厂商限制和许可证状态维护。

### 6.8 设置、隐私与诊断（P0）

- 输出目录、默认格式、并发数、通知、主题、语言和启动页偏好。
- 权限清单按功能申请，可在设置中查看、重新授权和跳转系统设置。
- 隐私页面说明：文件只在本地处理；哪些数据会产生网络请求；代理和下载数据的处理方式；日志保留时间。
- 诊断日志默认关闭敏感内容；用户主动导出前进行脱敏预览。
- 开源许可页列出四个上游项目、版本/提交号、许可证全文链接及所有直接依赖。

## 7. 跨模块集成要求

1. **统一任务模型**：`id、type、state、progress、createdAt、updatedAt、error、outputUris`；任务状态至少包括排队、运行、暂停、成功、失败、取消。
2. **统一文件模型**：使用 `content://` URI 和 SAF；模块不得假设固定绝对路径。
3. **代理注入**：仅网络请求型模块显式选择是否走 VPN/代理；不得绕过系统网络策略。
4. **统一通知**：每个长任务一个通知渠道，支持点击回到任务详情；通知不泄露媒体标题中的敏感信息（可配置）。
5. **统一错误码**：权限不足、网络不可用、空间不足、格式不支持、用户取消、依赖缺失、未知错误。
6. **模块隔离**：清理模块不得读取代理密钥；图片模块不得访问下载历史以外的媒体元数据；各模块可独立禁用和更新。

## 8. 技术与兼容性要求（供研发评审）

- Android 最低版本建议 API 26，首发适配最近 3 个 Android 大版本及主流 arm64 设备。
- 采用“复用优先”的模块化架构：应用壳、共享核心、代理、清理、媒体、图片五个边界；每个功能模块首先复用对应上游项目的成熟实现，再通过适配器接入统一体验。
- 长任务使用 WorkManager/前台服务等合规机制；代理使用 `VpnService`。
- 数据库保存任务、配置元数据和清理回收站索引；大文件和媒体内容不进入数据库。
- 支持深色模式、横屏/平板布局、TalkBack、动态字体和中文/英文。
- 上游依赖固定版本并记录 SBOM；安全补丁和解析器更新可独立发布。

### 8.1 架构边界与低耦合规则（强制）

| 层级/模块 | 职责 | 依赖限制 |
| --- | --- | --- |
| `app-shell` | 导航、主题、权限入口、全局错误页、依赖装配 | 仅依赖各模块公开 API，不包含业务实现 |
| `core-model` | 任务、文件、错误、日志、设置等纯数据模型和接口 | 不依赖 Android UI、上游项目或具体功能模块 |
| `core-platform` | 数据库、SAF、通知、加密、网络、后台任务、诊断 | 仅实现平台能力，不知道代理/清理/媒体/图片业务细节 |
| `feature-proxy` | 复用 FlClash 能力后的代理流程和统一 UI | 只依赖 core 接口及 `proxy-engine` 适配器 |
| `feature-cleaner` | 复用 sdmaid-se 能力后的清理流程和统一 UI | 只依赖 core 接口及 `cleaner-engine` 适配器 |
| `feature-media` | 复用 ytdlnis 能力后的媒体流程和统一 UI | 只依赖 core 接口及 `media-engine` 适配器 |
| `feature-image` | 复用 ImageToolbox 能力后的图片流程和统一 UI | 只依赖 core 接口及 `image-engine` 适配器 |
| `*-engine` | 上游项目、原生库、命令行组件或独立进程的受控封装 | 不依赖其他 feature；通过稳定接口向 feature 暴露上游能力 |

- 禁止 feature 模块直接引用其他 feature 的内部类、数据库表、页面路由或上游 SDK；跨模块协作只通过 `core-model` 定义的接口、事件和数据契约。
- 四个上游项目一律接入到各自 `*-engine` 适配器后。应用壳只做统一导航、工具箱、权限、任务中心、主题、设置、日志和跨模块契约；具体代理、清理、解析下载和图片处理逻辑优先保留在上游实现及其 Fork 中。
- 任何替换、升级、禁用或许可证隔离只能影响该适配器，不得改动其余三个业务模块。上游不能直接集成时，适配器可以通过受控进程、IPC 或命令封装调用，但不得把其功能重新散落实现到 app-shell 或其他 feature 中。
- 每个模块必须提供：能力声明、初始化/关闭、健康检查、版本信息、错误映射和 mock 实现，以支持独立开发与测试。
- 不允许共享“万能工具类”、跨模块单例或直接全局可写状态。依赖方向由构建规则检查，循环依赖视为构建失败。
- 共享数据模型必须版本化；字段新增保持向后兼容，破坏性变更通过迁移和兼容读取完成。

### 8.2 动画与流程体验规范（强制）

动画服务于状态理解和操作反馈，不作为装饰，也不得延长用户完成任务的时间。

- 页面进入/退出、底部导航切换、工具卡片排序、分组展开、任务进度、成功/失败反馈均使用一致的 Material Motion 风格过渡。
- 页面和卡片过渡默认 150-250ms；拖拽排序使用即时跟随和占位动画；长任务只更新进度，不循环播放醒目动画。
- 清理确认、VPN 连接、下载取消、删除文件等高风险流程，以明确状态、二次确认、进度和结果为主；动画不能遮挡确认文本、禁用按钮或延迟取消。
- 读取 Android 系统“移除动画/减少动态效果”偏好。开启后，所有非必要运动替换为即时状态切换或 0-50ms 淡入淡出。
- 动画必须可中断：返回、切换模块、屏幕旋转、进入后台或任务失败时，不得造成界面卡住、重复提交或状态错乱。
- 不使用闪烁、自动播放大面积动效、无意义循环动效；深色模式和低性能设备保持同等可用性。

### 8.3 可靠性、错误隔离与恢复（强制）

- 所有后台任务采用持久化状态机：`排队 -> 准备 -> 运行 -> 暂停/取消/成功/失败`；每次状态转换记录时间、原因和可恢复条件。
- 进程被杀、设备重启、网络切换、存储权限失效或前台服务停止后，任务必须恢复、重试、等待用户授权或明确失败，不能长期停留在“运行中”。
- 每个任务使用幂等任务 ID、输入快照和输出临时文件；重试不重复删除文件、不重复扣除资源、不覆盖用户原文件。
- 代理内核、媒体解析器、图片原生库异常必须被引擎适配器捕获并映射为统一错误；单个模块崩溃不得导致工具箱、设置或其他模块不可用。
- 清理与文件写入采用“预检 -> 临时输出/回收站 -> 原子提交 -> 结果核验”流程；空间不足、文件变化和权限撤销均需安全回滚或保留原文件。
- 所有不可恢复错误记录脱敏诊断信息；用户可选择导出日志，默认不上传任何日志、文件、URL、订阅或 Cookies。

### 8.4 工程管理与质量门禁（强制）

1. **需求可追踪**：每项功能需求使用稳定编号（例如 `BOX-01`、`PRO-01`），关联设计、实现模块、自动化测试和发布版本。
2. **上游复用台账**：每一项对用户可见的工具能力均须关联第 6.6 节的来源记录，包含上游 commit、复用方式、代码路径、差异、验证结果、更新策略和维护责任人；没有台账记录不得宣称“已整合”。
3. **ADR 决策记录**：上游集成方式、未复用原因、许可证策略、任务框架、数据库迁移、代理内核和媒体二进制更新等架构决策必须记录背景、选项、结论与后果。
4. **分支与评审**：功能分支必须经过至少一名审阅者；架构边界、权限、文件删除、VPN、媒体下载、原生库及 Fork 同步改动需要模块负责人审阅。
5. **持续集成**：每次合并请求运行格式化、静态检查、依赖/许可证扫描、上游适配器契约测试、单元测试、模块集成测试和 debug 构建；任一失败禁止合并。
6. **测试分层**：核心状态机、规则和文件操作有单元测试；适配器有上游行为对照/契约测试；关键用户流程有 UI/端到端测试；真实设备覆盖 API 26、主流版本、低内存设备和不同 ABI。
7. **发布门禁**：发布前必须完成上游版本差异审查、回归清单、崩溃监控检查、权限审计、SBOM、许可证清单、隐私检查、升级/降级验证及回滚包验证。
8. **可观测性**：记录脱敏的启动耗时、任务成功率、失败类别、ANR、崩溃和恢复率；设定阈值，超过阈值停止灰度并回滚。
9. **文档交付物**：维护上游复用台账、模块 README、接口契约、Fork 同步说明、数据迁移说明、故障处理手册、测试矩阵、发布清单和变更日志；新成员应可按文档独立搭建与验证模块。

## 11. 验收标准

- 新用户在无权限状态下启动，仍可浏览首页和进入不需要权限的模块。
- 工具箱页默认显示“全部 / 收藏 / 最近”分段、四个默认分组和四大模块入口；首次使用不出现空白或虚假历史记录。
- 用户可完成工具拖拽排序、跨组移动、隐藏/恢复、收藏、分组新建/重命名/删除、卡片尺寸切换和恢复默认；退出并重启应用后布局保持。
- 手机竖屏、横屏、平板、分屏和大字体模式下，工具卡片不重叠、不被底部操作区遮挡，所有操作入口满足 48dp 触控和 TalkBack 可用。
- 页面切换、分组展开、拖拽排序和任务反馈动画遵守动画规范；启用系统减少动画后，界面保持完整可用且不出现卡顿、重复提交或状态错乱。
- 代理连接、断开、失败和系统 VPN 冲突均有正确状态，不影响其他模块。
- 清理前可逐项预览，取消后不删除文件；断电/进程被杀后任务状态可恢复或明确失败。
- 媒体任务可加入至少 10 个队列项，单项暂停/恢复/取消互不影响。
- 图片批处理 50 张中等分辨率图片不崩溃，失败项可单独重试。
- Android 13、14、15（或发行时最近三个版本）完成核心流程回归；中英文、深色模式、TalkBack 无阻断问题。
- 四个 feature 模块无法直接访问彼此内部实现；构建依赖检查、适配器契约测试、任务状态机测试和关键流程端到端测试均通过后才能发布。
- 在网络切换、权限撤销、设备重启、进程被杀、空间不足和上游引擎崩溃场景下，任务均可恢复、重试或明确失败，且不会丢失原文件或停留在错误状态。
- 发布包包含隐私政策、第三方声明、开源许可证和可联系的安全问题反馈渠道。
