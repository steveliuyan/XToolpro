# Architecture Decision Records

Create one ADR for any decision that changes upstream reuse, licensing, module boundaries, build/toolchain, task persistence, storage safety, network/VPN behavior, binary distribution, or release policy.

Use filenames such as `ADR-0001-android-shell-stack.md`.

Each ADR contains: status, date, context, decision drivers, options considered, decision, consequences, rollback, links to specs, and links to reuse-ledger rows. ADRs are immutable after acceptance; supersede them with a later ADR rather than rewriting history.
